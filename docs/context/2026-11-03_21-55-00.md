## What the audit found, and what was actually broken

The important one is a regression the implementer introduced while fixing the complaint before it. The
detour route at the six verbatim blanks carried a clause `VERBATIM_FACT_SLOTS.has(slot) && trimmed.includes(" ")`
— *any multi-word message at a blank gets offered to the corpus first*. Measured against the live index:

| Message | Resolver | As a project name | What the clause did |
|---|---|---|---|
| `social media` | ANSWER `contact.socials` **1.000** | entirely plausible | answered about the studio; the brief stored nothing |
| `brand identity` | ANSWER `services.detail.integrated-creativity` **1.000** | entirely plausible | same |
| `demand generation` | ANSWER its own service page **1.000** | entirely plausible | same |
| `any discount available` | DISAMBIGUATE **0.647** | — | `engine.lookup` returns null on a disambiguation, so **the clause never once fired for the case it was written for** |

Having an answer is not evidence of a question. The clause is deleted; the routes into a detour are now the
shape of the sentence (`looksLikeQuestion`) and a chat abbreviation at its head (new
`opensWithChatShorthand`), both of which read the message rather than the corpus. The last-chance refusal
branch takes the same two signals, so a shorthand-led message the corpus cannot answer is refused rather
than filed — `u offer web design` moved from filed to refused; `abt pricing` gets the pricing answer.

The other findings, with what they turned out to be:

1. **MAJOR — negative controls that could not fail.** `assert.notEqual(result.kind, 'answer')` is green for
   a disambiguation, i.e. for the failure mode it was guarding. Now pins the four measured states in order:
   `fallback, fallback, disambiguate, disambiguate` (dissertations and printer repair have no candidate
   above the floor; weather-in-Calicut and visa-letter reach `location` 0.780 and `work.clients` 0.611).
   Reaching `fallback` on those two would need a threshold, and the thresholds are frozen — disclosed
   instead of quietly moved.
2. **MAJOR — the browser gate proved the branch that already worked.** The name-blank gate typed an
   auxiliary-led message (shape-only path) while the hijack above lived in the content path and had no gate
   at all. Two new gates close that: `a project name the corpus also sells is filed, not answered` and
   `a blank written in the chat register is answered, not filed`. `atTheNameBlank` became the general
   `atTheBlank(page, placeholder)`.
3. **MINOR — a reflow could teleport an in-flight glide.** The `ResizeObserver` gated on `anchored.current`
   and then wrote `node.scrollTop = end` mid-glide. It still retargets `destination` (a stale floor makes
   the *Jump to the latest* pill lie and turns a reflow into a false takeover) but retargets the smooth
   move instead of snapping while `gliding.current` is true.
4. **MINOR — the height gate measured the wrong geometry, and behind it was a real layout defect.** The
   844×390 gate passes only because `@media (max-width: 1023px)` wins on *width*, so a landscape phone gets
   the sheet; the floating panel's `26rem` floor was never exercised, and the gate's docstring cited a
   `max-width: 480px` rule that is not the one that applies. At 1280×400 the float asks for 416 px, floats
   ~80 px off the bottom above the launcher (`--pod-y`), and put its header **48 px above the screen**.
   `.panel` height is now `min(clamp(26rem, 74vh, 40rem), calc(100vh − var(--pod-y) − keyboard − 1rem))`;
   the first cap attempt, which subtracted a fixed 2 rem, left `top = −48` and failed its own gate.
5. **MINOR — the composer could eat its own content.** `.field` is capped at 8.75 rem with
   `overflow-y: hidden`; on engines that honour `field-sizing: content` the box grows to the cap and the
   lines under it are unreachable — a visitor's own brief, silently gone. `overflow-y: auto` now lives in
   CSS for every engine and the redundant inline write in `Composer.tsx` is deleted. The unit contract that
   *counted* `overflow-y: auto` in the stylesheet now names its owners (`.flow`, `.field`), because the
   count was exactly one while this defect was live.

**Not defects, recorded because they were reported:** `isScaffold` checking the stop-word set before the
`known` guard is deliberate — `known` is `index.vocabulary`, which contains every authored word including
`you`, `are`, `what`, so reordering would promote grammar to content and move scores across the frozen
table. `profile-modal-open` is not a dead class write: `FloatingExploreButton.module.scss` and
`CompanyProfileModal.module.scss` both style on it. `.menu` outside the scroll column is intentional.

Three small ones went with the fixes: `folded()` uses `Object.hasOwn`, so a message containing the inherited
name `constructor` can no longer fold to a function (both cases gated); the duplicate fallback-lock constant
(local `LOCK_AFTER = 2` beside `FALLBACK_LIMIT = 2`) is one constant; and the comprehension probe takes
`phrase >> priorIntentId` so continuity can be asked from the command line instead of by editing the file.

## Disclosed

`Header.tsx` still has zero importers and the auditor recommends deleting it plus its stylesheet; deleting
shared code is the owner's call, so it stays with an inert lock edit. `any discount available` (DISAMBIGUATE
0.647) is still filed at a verbatim blank — no question shape, no chat abbreviation, and the honest fix is a
`company`-shaped slot rather than a name heuristic that would refuse `Brand & Co` and `The Marketing Club`.
A 400 px-tall desktop window leaves the conversation column **71 px** after the header, the progress rail
and the composer are paid for; the panel is inside the screen now, which is the fix, and the gate pins 64 px
rather than the number the argument produced. `CONTINUITY_PRIOR = 1.08` makes the effective cold-accept bar
≈0.741 for a same-family candidate — the boundary is now pinned inside the continuity gate
(`leader.score < 0.8` cold, `leader.score × 1.08 ≥ 0.8`). `X-Idempotency-Key` is sent and read by no route.
The root `playwright.config.ts` health-checks port 3000 while the studio server is the owner's on 3003, so
the admin, auth and site-wide accessibility specs were **not** run for this pass. The dev server these
gates ran against was started by this session after the owner's own had died.
