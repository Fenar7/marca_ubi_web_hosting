## Production authentication incident

The build first exposed missing Vercel Production values for `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`. After configuration was added, production sign-in returned the generic "Invalid corporate credentials" banner despite a successful direct password sign-in against the expected Supabase project.

The Vercel `provider_rejected` log confirmed `vxskliecxaxboxershnz.supabase.co`, HTTP 401, no provider code and no returned user. A controlled comparison on the same host showed that an invalid API key produces exactly that response shape, while invalid credentials with a valid public key produce HTTP 400 and `invalid_credentials`. The Vercel screenshot showed that the public key was missing its final character. The prescribed fix was to copy the complete publishable key into the exact app variable name, scope it to Production and redeploy. A later screenshot showed the Commercial Desk UI, with no separately recorded production browser verification.

The Root Admin account `admin@marcaubi.com` had its password reset per user request, and direct Supabase sign-in was verified. This register omits passwords, API keys, tokens and cookies. A privileged Supabase key and a password were shared in chat. Their subsequent rotation or revocation was not verified.
