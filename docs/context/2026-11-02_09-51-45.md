## 2. Architecture — the whole shape

Nine source modules under `src/app/chat-pod/` plus two shared modules the wizard now also uses. Total on-branch change: 50 files, +10,341/−262.

### 2.1 Mount gate (`ChatPodShell.tsx`)

The pod must never compete with the hero. Four conditions, in this order:

1. **Route exclusion** — `EXCLUDED_ROUTES = ["/start-project", "/studio", "/admin"]` matched as `pathname === route || pathname.startsWith(route + "/")`. `/start-project` is excluded because the long form is the primary surface there; `/studio` and `/admin` because an assistant on a CRM is a different product decision.
2. **`dynamic(..., { ssr: false, loading: () => null })`** — `ChatPod.tsx` reads `window`, `matchMedia` and `localStorage`, so a server render would be a lie. Consequence: with JS off, the launcher never paints, so there is no control that cannot work (R-26/R-27).
3. **Arrival after the intro loader** — the shell listens for the site's own loader event and releases the pod then, with `requestIdleCallback(release, { timeout: IDLE_DEADLINE_MS = 2_500 })` so a fast page still waits for idle, and `LOADER_BACKSTOP_MS = 12_000` so a loader that never fires cannot swallow the pod forever.
4. **`ChatPodBoundary`** — an error boundary so a defect inside the pod costs the pod, not the page.

### 2.2 Knowledge layer (server → props → client)

- **`knowledge/collect.ts`** is the only I/O. It gathers four Sanity sources in parallel behind `withTimeout(label, work, fallback)` with `SANITY_TIMEOUT_MS = 1_500`, falling back to the query modules' own published constants (`FALLBACK_FAQS`, `FALLBACK_CAREERS`) or `[]`, and logs every timeout or rejection with the query name. Memoised per server process for `COMPILE_TTL_MS = 60_000`, matching the blog listing's ISR cadence, so the mount cannot put four round-trips in front of every page render.
- **`knowledge/compile.ts`** is pure — no Sanity import, no `fetch` — which is what makes every figure the pod says assertable in a unit run. `compileKnowledgeBase(sources)` derives `services` from `SERVICE_DETAILS`, journal entries from the published posts (`JOURNAL_LIMIT = 12`, dates formatted `en-GB` at compile time via `formatJournalDate` so the locale cannot drift to the visitor's device), FAQs and careers filtered to non-empty, the process principles and studio facts from `corpus.ts`, and `counts` where **every count is the length of the array printed next to it**. Live compile: 16 service pages, 8 + 8 by split, 52 service options, 8 categories, 4 journal posts, 5 FAQs, 3 open roles.
- **`knowledge/corpus.ts`** holds the authored, non-Sanity half: `PERSONA` (D2 `Ubi`), `STUDIO` facts transcribed from `MonumentalFooter.tsx` / `ConnectCutout.tsx`, `PROCESS_PRINCIPLES`, `PERSISTENT_MENU`, `BANNED_TERMS`, `DRAFT_RETENTION_DAYS = 14`.
- **`knowledge/intents.ts`** — **23 intents**, each with `utterances`, `keywords`, `respond(kb)` and a mandatory `source`. The coverage suite fails the build if any intent lacks provenance, if a chip points at a missing intent id, if a `route` chip's href does not resolve to a real `page.tsx` on disk, or if an emitted answer contains a banned term or an em dash.
- The compiled object crosses the props boundary as **plain JSON by contract** (`KnowledgeBase`), which is what lets a visitor's message be answered with zero network requests.

### 2.3 Conversation engine (client, deterministic)

- **`engine/normalise.ts`** — lowercase, strip `[/\\&,_\-–—]`, diacritic fold, tokenise. One implementation, so tier 1 and tier 2 cannot disagree about what "the same word" means.
- **`engine/match.ts`** — three tiers, no model: **tier 1** exact utterance after normalisation (confidence 1.0); **tier 2** keyword scoring, first token weighted 1.0 and the rest 0.6; **tier 3** fuzzy `editSimilarity` + `tokenOverlap` against `keywords`, with a margin requirement so a near-tie never silently resolves. Below margin → disambiguation chips instead of an answer.
- **`engine/useChatEngine.ts`** — builds the inverted index once per knowledge object, resolves a reply, and owns the honesty limit: after `LOCK_AFTER = 2` unmatched visits the pod stops guessing and says so (`FALLBACK_REPLIES.capped`). It now also exposes **`seedFallbacks(count)`** so a restored draft's counter is the visitor's real counter, not a reset one (§6 finding 4).

### 2.4 UI layer

`ChatPod.tsx` (877 lines) is the orchestrator; the rest renders. `PersonaHeader` (name, the permanent `Digital assistant · Not a person` disclosure, the menu), `Transcript` + `MessageBubble` (blocks: `p` / `list` / `links`; visitor echo on black fill, assistant on the 3.5 % tint; tabular `14:02` stamps), `ChipRow` (40 ms stagger, `data-count="0"` removes the tray entirely), `Composer` (`aria-disabled` rather than `disabled`, so a locked composer stays focusable and screen-reader-findable).

Two state machines drive it: the **chat engine** (which intent answered) and the **intake FSM** (which question is live). Effects in `ChatPod.tsx`: seed-once-open (`seeded` ref, because React 19 double-invokes effects in dev and two greetings is a bug a visitor sees), intake turn emitter (signature = `mode | active slot | slotIndex | attempt | error | phoneRequired`, so a re-ask reprints the question with the reason above it instead of duplicating the turn), submit effect, persistence effect, focus trap, scroll lock, nudge, timers.

Every `setTimeout` in the component goes through **`later(fn, ms)`**, which registers the id in a `Set` and clears the whole set on unmount — a stale nudge cue or a stale typing beat landing on an unmounted panel was otherwise reachable by closing the dialog mid-answer.

### 2.5 Intake: 17 slots, one builder, one route

- **`src/app/lib/intake/intakeOptions.ts`** is the single source for the five closed sets (`INTAKE_LANGUAGES`, `INTAKE_INDUSTRIES`, `INTAKE_REFERRAL_SOURCES`, `INTAKE_AGENCY_STATUS_OPTIONS`, `INTAKE_SHOWCASE_CHOICES`), plus `INTAKE_CATEGORIES`, `INTAKE_TIMELINE_OPTIONS`, `SERVICES_BY_CATEGORY`, and the two separators the wizard's own accumulators use (`MULTI_VALUE_SEPARATOR = ", "`, `LINK_VALUE_SEPARATOR = "\n"`) plus `splitLinks`. The four `ProjectForm` step files now **import** these; the parity suite proves it statically (a `const CATEGORIES = ["…"]` literal in any surface fails) as well as at runtime.
- **`intake/slots.ts`** — 17 slot definitions keyed exactly as `ProjectForm/types.ts` names them (`categories`/`services` are the arrays, `category`/`service` the joined strings), each with `question`, `label`, `kind` (`text` | `multi` | `links` | `pick`), `options` or a dynamic option resolver, `validate(raw, slots)`, requiredness and skip semantics.
- **`intake/useIntakeFlow.ts`** — the reducer. Modes `CHAT → INTAKE_FORM → REVIEW → SUBMITTING → DONE | ERROR`, with guards that refuse rather than mis-state: `SUBMIT` outside `REVIEW`, a second `SUBMIT` while in flight, `EXIT_TO_CHAT` while in flight, `EDIT_SLOT` outside the card, `RETRY` outside `ERROR`, and after `MAX_SUBMIT_ATTEMPTS = 3` failures the machine will not send again at all. Skipping the email promotes the phone (`phoneRequired`); `OPTIONAL_TAIL_START` marks where the required block ends. `SUBMIT_OK` clears the answers and records `sentTo` — the channel the reply will actually go to.
- **`intake/review.ts`** — `slotsToFields` (arrays joined with the wizard's separators), `reviewRows`, `replyChannel(slots)`, `buildPodPayload`.
- **`src/app/lib/intake/ingestPayload.ts`** — `buildIngestPayload(fields, { idempotencyKey, source })`, used by *both* surfaces. It assembles `notes` via `assembleCombinedNotes`, caps at `NOTES_MAX_CHARS = 2000` on a **whole-line boundary**, appends `NOTES_OVERFLOW_MARKER` and keeps the entire brief under `brief_payload[NOTES_OVERFLOW_KEY]` — the trap where a long brief 422s at the route.
- **`intake/submit.ts`** — `createIdempotencyKey()` (one per submission *intent*, reused by every retry) and `submitBrief` with `MAX_NETWORK_ATTEMPTS = 3`, linear backoff `attempt × 1000`, and an outcome union that tells the FSM whether the route named a field.
- **D1**: the pod POSTs to the live `POST /api/sales-funnel/ingest`. No new route, no schema change, no honeypot key (the route trips only on a *non-empty* honeypot, so absent and empty are the same request).

### 2.6 Storage and privacy (`persistence.ts`)

Three keys, two stores, one consent question:

| Key | Store | Holds | Scope |
|---|---|---|---|
| `mubi.pod.draft.v1` | `localStorage` | version, `savedAt`, ≤`DRAFT_MESSAGE_LIMIT = 40` messages, slot map, `fallbackCount` | 14 days (`isExpired`), only when consent is `true`, never in `DONE` |
| `mubi.pod.nudged` | `sessionStorage` | `"1"` | one tab — D5 says once per *session* |
| `mubi.pod.consent` | `localStorage` | `"true"` / `"false"` | never asked (`null`) is a third state, and the only one that shows the block |

`grantConsent(false)` calls `clearDraft()` — withdrawal deletes rather than pauses. Nothing leaves the browser except the single ingest POST; `grep` for `fetch(` inside the module returns that one call.

### 2.7 Accessibility contract

`role="dialog"` + `aria-modal="true"` + `aria-labelledby` on the panel; a single `role="log" aria-live="polite"` for the transcript (one live region, not one per bubble); capture-phase Tab trap that pulls focus to the nearer end if it ever escapes; Escape is contextual — the first press during intake stops the questions and keeps the answers, the second closes, and focus returns to the launcher. The launcher is named **from its own content** (`Ubi` + `Ask`/`Close` + one sr-only clause) because an `aria-label` on a two-line flex control can never contain its concatenated visible text — SC 2.5.3 `label-content-name-mismatch`, serious, on every route. A keyboard-visitor focus effect re-focuses the composer when a chip re-render drops focus to `document.body`, and only for keyboard visitors, so a mouse user is not ambushed.

## 3. What "same as the form" means, mechanically

`chatpod-ingest-payload-parity.test.ts` (33 tests) is the contract. It defines the same brief twice — once as `ProjectFormData`, once as 17 slot values — and asserts `deepStrictEqual` on both payloads after stripping `source_name`/`source_detail`, the only permitted difference. It also walks the brief through the **real reducer** (`podSlotsFromMachine()`) and asserts the machine's slots equal the mirror literal, so the parity claim is about what a visitor's clicks produce, not about what a test says they look like.

Closed-set guards: every surface imports the shared arrays (static source-text check *and* element-for-element comparison); stored values are byte-identical members including the straight apostrophe and capitalised `NOT` in the agency strings; the compact `chipLabel` never reaches the payload. Inspiration links round-trip through array → joined string → `splitLinks`. The historic separator collision is held **identical**, not fixed: "Postcard, flyer or print" splits into two services on both surfaces, because parity means "exactly as lossy as the form", not smarter than it.
