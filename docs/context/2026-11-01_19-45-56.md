## 3. The rule that took five rejections to learn

**The reading column IS the measure.** No `max-width` cap anywhere in `/blog/[slug]` prose —
not in rem, not in `ch`, not derived from the font size. Text, headings, lists, callouts and
code all reach the column edge. Line length is held by keeping the type *small and normal*
(16-18px body), not by capping width and not by inflating type.

Do not "fix" this back to a 65-85ch measure. It has been tried five times and every attempt
was rejected as wasted space. Same class of failure: the `01`/`02` section-numeral rail, which
reserved 153px of gutter to display a number that restated the heading.

**The only surviving numerals** are the `01`/`02`/`03` row indices in the "More from the
journal" ledger at the foot of the article ([`BlogPost.module.scss:748`](../src/app/blog/%5Bslug%5D/BlogPost.module.scss)).
Those number a list of three different articles and mirror the `/blog` index ledger. The user
has not asked for them to go; if they complain about numerals again, that block is the target.

--grid-gap     clamp(2rem, 4vw, 4rem)
--rail-w       260px, 300px above 1500px, 0 at or below 1024px

- Container `max-width: 1680px`, page `padding` uses `--page-gutter`.

  the CSS `counter-*` pair, `.heading2::before`, `data-variant` on callouts) must stay deleted.
  `grep -rn -- "--measure" src/app/` returns nothing; keep it that way.
- Below 1024px the rail becomes a hairline strip *above* the prose (grid-row 1, `order: -1`),
  progress + TOC drop out, sharing stays. The strip flattens the share rows through the

## 7. Data & Sanity facts worth knowing

- `estimatedReadingTime` is **required and non-nullable** on `Post`
  ([`src/sanity/types/blog.ts:66`](../src/sanity/types/blog.ts)), so `?? 4` fallbacks were dead
  code, not fabricated numbers. `PostSummary = Omit<Post, "body" | "seo">` carries **no body**,
  so a related-post row cannot derive a read time — the cell is omitted instead of invented.
- `coverUrl(source, w, h)` is the hotspot-aware crop path; raw `asset.url` originals were
  shipping multi-MB `<img>` tags. `placeholder="blur"` is gated on `asset.metadata.lqip`
  existing, because `next/image` throws on `blur` without a `blurDataURL`.
- No-cover cards render a per-card initial plate derived from the category, never a stock
  fallback; an empty query renders an honest note pointing at `/blog`.
- The listing's reading-time column is derived from the row's own `publishedAt` (single source
  of truth) rather than a second field.

## 8. Traps already paid for

1. **`position: sticky` needs travel.** A sticky element inside a grid item sized by
   `align-items: start` has a zero-height containing block and never pins. Put sticky on the
   grid item itself (confined by the grid area), or give the item `align-self: stretch`.
   The homepage rail was fixed this way ([`DispatchesCurtain.module.scss`](../src/app/components/Sections/DispatchesCurtain.module.scss):
   sticky moved from `.stickyRail` to `.leftColumn`).
2. **JSX entities:** `&nearr;` is not decoded and renders literally. `&rarr;` works. Use
   `{"\u2197"}` for the north-east arrow.
3. **`overflow-x: clip` on html/body is sticky-safe; `overflow: hidden` is not.** Lenis smooth
   scroll is present.
4. **Circulars weights:** 400/500/700 exist, 600 and 450 never render on the loaded cuts.
5. **Never legacy orange** `#ff6100`. Accent is `#ea002a`, hover `#c40023`.
6. **Playwright scripts** must live inside the repo (e.g. `node_modules/mu-scratch/`) or module
   resolution fails; homepage `networkidle` never settles behind the background video — use
   `domcontentloaded` + `waitForSelector('#dispatches')`.
