## The one MAJOR, and why it is not live

The auditor found a **second viewport lock that leaks**: `Header.tsx` writes `html/body.menu-open`,
`Header.module.scss` declares `overflow: hidden` under that class, and the class is removed only in the GSAP
`onReverseComplete` — which the lock module's own docstring says does not run when a reverse is interrupted.
Traced carefully, the page would stay locked with an empty refcount.

Measured against the repository, every link in that chain is correct **except the one that matters**:

- `grep` for any import of `components/Header` across `src` → **nothing**. The component has had zero
  importers since before this branch; the live header is `ClientHeader` + `NavigationOverlay`.
- Every writer of `menu-open` in the public tree is inside that dead file (`Header.tsx:74-75, 86-87, 224-225`).
- A CSS module imported only by a component nobody imports is never emitted, so the `overflow: hidden` rule
  is not in the bundle. `FloatingExploreButton.module.scss:25` styles `:global(body.menu-open) &` and so is
  itself inert in the live path — pre-existing, unrelated to the lock.
- The only `document.body.style.overflow` writers outside `overlayScrollLock.ts` anywhere in `src` are five
  admin-route components, a different route tree that mounts neither the pod nor the drawer.

So the leak is real code that cannot run. It is recorded because it is the second audit in a row to be
misled by `Header.tsx`, and the cheapest way to stop paying that tax is to delete the file — which remains
the owner's call, asked for twice and not yet given.

## What the audit produced that was real

1. **The scroll-surface contract could not see a regression** — it matched the literal `overflow-y: auto`, so
   `overflow: auto`, `overflow-y:scroll`, or a no-space variant would keep it green while putting a second
   scrollbar back in the panel. Fixed: the gate now walks the stylesheet line by line, remembers the last
   selector and reports the *owners* of every scrolling declaration, asserting `['.field', '.flow']`. Proved
   by mutation rather than by argument — `overflow: auto` injected on `.tray` failed the gate with the same
   assertion the real defect would produce; the file was reverted from git and the gate went green again.
2. **`looksLikeQuestion` refuses proper nouns that open like questions.** Measured, not theorised:
   `who wants a proposal`, `what the heck studio`, `do it forward`, `tell me nothing`, `how to damp the roof`
   all read as questions (case is folded before the sentence is read, so a title and an imperative are the
   same tokens); `will of the people`, `can on the water`, `arjun mehta`, `the marketing club` still file.
   At a verbatim blank the first group is refused rather than stored — a refusal is re-answerable, a stored
   question is a corrupt CRM record — and the trade-off is now pinned by a test that says so out loud, with
   the re-ask recorded as the open item that would retire it.
3. **`ResizeObserver` keys on `[children]`** and re-creates on every parent render. Left alone: the dependency
   is what lets it observe a row that did not exist last render. Churn, not a wrong number — documented as a
   disclosure rather than abstracted away.
4. **One lock token, one owner.** `acquire` early-returns for a held token, so two surfaces sharing a token
   would release for each other. True, and an assumption rather than a mechanism; the four tokens are four
   components, now written down in §7.10.
5. **The claims held where they were checked:** no `any`, no swallowed exception, no new dependency
   (`package.json` and the lockfile unchanged across the range), nothing in `engine/` reaching `fetch`, no
   secret in the diff, `tsc -p tsconfig.podcheck.json` exit 0, and the auditor's own unit run reported
   1333/0 rather than quoting this document.
