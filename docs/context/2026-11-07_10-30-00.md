# Local Development CSS Module Failure

## Symptom

Next.js 16 development startup failed while transforming `AvatarUploadModal.module.scss.module.css` with `Selector "*" is not pure`. The SCSS module source itself did not contain a universal selector, and standalone Sass compilation succeeded.

## Root cause

The generated Turbopack CSS chunk for this module contained Tailwind v4's global preflight selectors (`*`, `:before`, and `:after`) alongside the module styles. Turbopack then applied CSS Module purity validation to the combined chunk. This is a local development bundler interaction; the production Vercel build had passed.

## Resolution

- `npm run dev` and `npm run dev:clean` use Next's supported webpack dev bundler.
- `npm run dev:turbo` explicitly opts into Turbopack for diagnosis or when the bundler issue is resolved upstream.
- Existing dev-server processes must be stopped and restarted for the script change to take effect. No running process was terminated as part of this change.

## Validation and limits

- Confirmed the installed Next 16.1.6 CLI supports `--webpack` and `--turbopack`.
- No application styles or module selectors were changed; the fix selects a compatible local dev bundler.
- Browser smoke testing was not performed in this change. Recheck the Avatar upload modal and team page after restarting with `npm run dev`.
