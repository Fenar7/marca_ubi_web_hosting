## 2. Root Cause Analysis
1. **Fatal PostgREST Error `PGRST200` on `/admin/tasks`**:
   - `src/app/admin/(workspace)/tasks/page.tsx` embedded `profiles:crm_team_directory!leads_assigned_to_fkey(full_name)` in the primary `leads` select.
   - In PostgreSQL, foreign keys (`leads_assigned_to_fkey`) exist strictly on base physical tables (`public.profiles`), never on views.
   - When PostgREST attempts to evaluate the constraint hint against the view `public.crm_team_directory`, it rejects the request with code `PGRST200` ("Could not find a relationship between 'leads' and 'crm_team_directory' in the schema cache").
2. **Schema Cache Invalidation `PGRST205` on Directory Queries**:
   - The view `crm_team_directory` was introduced in migration `20261105000001_preserve_activity_attribution_and_history.sql`.
   - When this view is unapplied or PostgREST has not reloaded its schema cache, direct queries to `crm_team_directory` fail with `PGRST205`.

## 3. Implemented Architecture & Solutions
1. **Centralized Directory Resilience Helper (`src/app/admin/lib/crmDirectory.ts`)**:
   - Implemented `getCrmDirectoryMap(supabase, ownerIds)` and `getCrmDirectoryList(supabase, filterRoles)`.
   - Tier 1: Queries `public.crm_team_directory`.
   - Tier 2 (Safe Fallback): Queries `public.profiles` with `status = 'active'`.
   - Tier 3 (Graceful Degradation): Returns empty collections without throwing or halting page execution.
2. **Decoupled Task & Work Page Queries**:
   - `src/app/admin/(workspace)/tasks/page.tsx`: Removed embedded view join from `baseRows`. Fetches unique assignee IDs and resolves names post-query using `getCrmDirectoryMap`.
   - `src/app/admin/(workspace)/works/page.tsx`: Decoupled `client_works` query from `crm_team_directory!client_works_creative_lead_id_fkey` and `tech_lead_id_fkey`. Resolves creative/tech lead names post-query and queries director list with automatic fallback via `getCrmDirectoryList`.
3. **Physical Table Joins for Dossier & Activity Server Actions**:
   - `src/app/actions/leads.ts`: Swapped `crm_team_directory` in `getActiveTeamAssignees` to use `getCrmDirectoryList(supabase, ['admin', 'sales_manager', 'sales_executive'])`. Changed dossier and activity queries to join the base table `profiles:profiles!leads_assigned_to_fkey` and `profiles:profiles!lead_activities_actor_id_fkey`.
   - `src/app/actions/leadActivityActions.ts`: Changed `lead_activities` select to join `profiles:profiles!lead_activities_actor_id_fkey`.
4. **RLS Security Verification**:
   - Audited RLS policy `profiles_select_scoped`. Non-administrative callers are kernel-restricted to their own profile (`id = auth.uid()`), guaranteeing zero data leakage on fallback.
5. **Automated Verification**:
