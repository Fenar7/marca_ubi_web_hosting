## What the owner said

A screenshot of the open panel and one paragraph: two scrollbars inside one view, *the scrolls are not
working* on other pages too, and `can yu pls tell me about services` still not understood — *now i feel
like a dumb chatbot*. The mission attached to it was an implementation mandate, not an analysis request:
execute the remediation plan, then have independent auditors review it without trusting the implementer.

## What shipped

**One scroll owner.** The message list and the chip tray used to be two `overflow-y: auto` boxes stacked
inside a fixed-height panel — a filing cabinet, not a conversation. `.flow` is now the only scroller; the
transcript is `flex: 1 0 auto` inside it and the tray is passed as the tail of the same column. Follow
targets the floor (`scrollHeight - clientHeight`), the arriving row's height is added to `scrollTop` in the
pre-paint frame, and `overflow-anchor: none` stops the browser compensating against a destination the pod
computes itself. A `ResizeObserver` over the box *and its children* keeps `lastExtent` and the floor honest
between React commits — font swap, rail re-wrap and the keyboard inset all move the geometry while React
sits still.

**One lock on the viewport.** New `src/app/lib/overlayScrollLock.ts`: a refcounted `Set` of tokens with
`acquire` / `release` / `isOverlayScrollLocked` / `onOverlayScrollLockChange` and a `useOverlayScrollLock`
hook. `site-navigation`, `company-profile`, `reel-modal` and `chat-pod` hold it; none of them writes
`document.body.style.overflow` any more, and `SmoothScrollProvider` stops and starts Lenis from the lock
instead of from four bespoke window events and a `classList.contains` guess. A subscriber is told the
current truth when it subscribes — the class-reading version lost that race on every slow first load.
Lenis 1.3.17 cancels wheel and `touchmove` outside a `data-lenis-prevent` subtree *even when stopped*, so
all four overlays now carry the exemption and a unit test asserts it.

**Question recognition, three holes closed.** `isScaffold` forgives four-character tokens against
`INTERROGATIVE_SWAPS` only (adjacent transpositions of the openers — never the whole stop-word set, because
`from` ↔ `form` eats a subject). `looksLikeQuestion` gained the trailing-interrogative branch
(`the services are which`) and `please` in the request family (`pls send info`, folded before the opening is
read). At the six verbatim slots, a message with a question shape **or** one the corpus can confidently
answer is routed to `engine.lookup` before it can be filed — a second route, not a stricter heuristic.
Measured: `whta do you do` 0.852 ANSWER (was DISAMBIGUATE), `whta is marka ubi` 1.000,
`the services are which` 1.000, `abt pricing` 1.000, `wat is your price` refused on shape.

**One harness bug of its own.** The multi-select tap-stability gate failed by 32 px and the pod was not
guilty: Playwright's `focus()` scrolls the target into view, so the gate measured its own scroll and
reported it as a defect. `tapInPlace()` focuses with `preventScroll`, and baselines are taken after the
600 ms glide (`GLIDE_SETTLE_MS`) because `boundingBox()` includes transforms.

## Disclosed

`Header.tsx` has zero importers, so its lock edit is inert. `any discount available` and `u offer web
design` are still filed at a name blank — no question shape, no confident corpus answer, and a stop-word
heuristic would refuse real company names. `CONTINUITY_PRIOR = 1.08` makes the effective cold-accept bar
≈0.741 for same-family candidates. `X-Idempotency-Key` is sent and unread by any route. The root
`playwright.config.ts` health-checks port 3000 and the studio server is the user's on 3003, so the admin,
auth and site-wide accessibility specs were **not** run for this pass. The dev server these gates ran
against was started by this session after the user's own had died.
