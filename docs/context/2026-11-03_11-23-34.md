## 1. What the owner reported, and what it actually was

Two complaints started this phase, both from live use of the pod:

1. *"when i ask what is the services or what are the services available it can't understand that, and when
   asking about services it says there are 16 services — that doesn't help; in that case it should ask b2b
   or b2c … then explain about each service."* The pod was answering. It was answering the wrong question:
   the count of the catalogue is not a description of it, and a visitor who does not know the vocabulary
   cannot pick from a list keyed by that vocabulary.
2. *"there should be fluid noises, you know, when sending message etc."* The surface felt dead: no motion
   carrying a send, no receipt, no hand-off.

A third, later: *"the other thing is there are many bugs in this."* Four turned out to be real defects, and
all four were found by measuring rather than by reading the code (see §4).

## 2. Part A — comprehension, resolver, conversation state (A1–A9)

Scope: `engine/match.ts`, `engine/normalise.ts`, the new `engine/context.ts`, `engine/useChatEngine.ts`,
`types.ts`, `knowledge/corpus.ts`, `knowledge/intents.ts`.

- **A1/A2 — normalisation and keyword hygiene.** Input is folded, separators (including en/em dashes,
  `engine/normalise.ts:16`) stripped, and tokens scored against a coverage model rather than a substring
  hit-list.
- **A3/A4 — the three-tier resolver.** `ACCEPT_THRESHOLD 0.8`, `ACCEPT_MARGIN 0.15` for a confident single
  answer; `FLOOR_THRESHOLD 0.55` with `DISAMBIGUATION_WIDTH 3` to ask *which* instead of guessing; below
  the floor, a soft or hard fallback. Two consecutive misses `LOCK_AFTER 2` stop the pod guessing, and it
  says why rather than re-asking the same question.
- **A5 — the services branch the owner asked for.** An overview no longer recites `16 services`; it splits
  the catalogue on the axis the studio already publishes (B2B / B2C), explains the lines, and offers the
  per-service depth as the next step.
- **A6 — per-service depth.** `respond` now receives an `AnswerContext` (`types.ts`), so "tell me more"
  renders the same service with its sub-service list attached. A third ask prints nothing new: the pod
  says the subject has run out and re-attaches the live chips.
- **A7/A8 — conversation state.** `engine/context.ts` (289 new lines) holds the previous turn: the intent
  answered, the chips rendered, and a fingerprint of the blocks that were shown. That is what makes
  "the second one", "tell me more" and a bare chip name resolve. `FollowUp` has three shapes — `depth`,
  `chip`, `refused` — and authoring outranks the idiom layer, so a message that is genuinely about another
  topic is answered as a new question. Ordinals accept digits (`ORDINAL_DIGIT`), and a digit beyond the
  list is answered with the honest size of the list rather than a refusal.
- **A9 — the LLM phase is specified, not built** (doc 20 §7). Everything here stays offline, deterministic
  and source-traceable.

## 6. Rules learned the hard way (do not re-litigate)

- **A colour's number is the number that gets painted.** Alpha composites must be rounded to 8 bits before
  the ratio, and a graphic's floor belongs to its faintest frame, including the reduced-motion resting
  state. Unrounded arithmetic gives 4.68 where the browser gives 4.69.
- **`aria-disabled` ≠ `disabled`.** Focusable + informative means the AA floor still applies to the ink.
- **Never widen a threshold to make a test pass**, and never edit the app to satisfy a broken assertion:
  defect 2 was a test bug, and the app was right.
- **A claim in a comment is not evidence.** Anything the gate table asserts must be computable from the
  shipped file.
- **The host is memory-starved.** Playwright workers die with exit 134 / 3221226505, and `tsc` OOMs. The
  dev server on `3003` belongs to the owner: probe it, reuse it, never kill or rebind it. Foreign processes
  from other projects (`C:\Fenar\Zenxvio\…`) were left alone even while they held gigabytes.
